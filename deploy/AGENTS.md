# deploy - Helm chart, ECS module, Grafana resources

## helm/

Chart `version` and `appVersion` are release-please-managed in `Chart.yaml`. Never hardcode a version
anywhere else in this tree.

- **`genai-otel-bridge.selectorLabels` is the immutable Deployment and PDB selector.** Keep it the
  minimal `app: genai-otel-bridge`. Folding version, instance or chart labels into it breaks
  `helm upgrade` over an existing Deployment, because the selector is immutable post-create. The
  richer `genai-otel-bridge.labels` block includes it and is what everything else uses.
- **RBAC is a Role, not a ClusterRole**, and is `resourceNames`-scoped as well as namespaced: leases
  get/update only on `genai-otel-bridge-leader`, configmaps get/update only on
  `genai-otel-bridge-checkpoints`, so the pod cannot touch its own config CM. `create` stays unscoped
  because RBAC `resourceNames` cannot gate `create` - the name does not exist yet.
- **NetworkPolicy: select the DNS pods by label, never by CIDR.** kube-router and the VPC CNI
  evaluate egress against the post-DNAT CoreDNS *pod* IP, so a service-CIDR rule silently breaks DNS
  on k3s and EKS. The rule targets kube-system plus `k8s-app: kube-dns`. Ingress is default-deny
  except the health port from any source: self-metrics are OTLP-pushed, nothing scrapes the pod, so
  the kubelet probe is the only legitimate inbound and a blanket default-deny-ingress is a
  CNI-dependent footgun. `apiServerCIDR` is required for lease and checkpoint, and is kept separate
  from the OTLP CIDR so that one can be tightened independently. On EKS, enforcement needs the
  VPC-CNI network-policy feature or Calico.
- **`cleanup-hook.yaml` is `post-delete`, not `pre-delete`.** The binary creates the Lease and
  checkpoint ConfigMap at runtime, so `helm uninstall` does not track them. pre-delete would run
  while the Deployment is still up and the live leader would immediately re-create them. The hook
  uses a dedicated, ephemeral, delete-only, `resourceNames`-scoped SA/Role/RoleBinding, not the app's
  Role: by post-delete the app RBAC is already gone, and the running app must never carry `delete`.
  `cleanup.retainCheckpoint` keeps the checkpoint CM for resume-on-reinstall and drops the configmap
  grant from the hook Role. A failed hook degrades to orphaned objects, never blocks the uninstall.
- **`podDisruptionBudget` uses `maxUnavailable`, not `minAvailable`,** so it is a no-op at
  `replicas: 1` and cannot deadlock a single-node dev drain.
- **Shutdown is a hard cancel, not a drain.** The lease is never released, it expires, so a standby
  cannot acquire mid-shutdown; `leaderCtx` cancels immediately on SIGTERM. The termination grace
  period bounds time-to-SIGKILL and covers the emit-retry budget; it is not a drain-to-completion
  window.
- The `checksum/config` pod annotation (gated by `rolloutOnConfigChange`) hashes **only**
  `templates/configmap.yaml`, never the app-created checkpoint state CM.
- Topology spread is by host **and** zone, both `ScheduleAnyway`, so a single-node or single-AZ dev
  cluster still schedules while multi-AZ EKS lands the standby elsewhere.
- **The `config:` map in `values.yaml` (between the `# >>> BEGIN/END generated config <<<` markers)
  is generated by `just gen` from the Go structs. Never hand-edit it.** Tag semantics, regen workflow
  and the drift gate live in `internal/config/AGENTS.md`. Chart-side only: `toYaml` strips comments
  and sorts keys, which is fine because the rendered ConfigMap is data and `${ENV}` refs are scalar
  strings; the verbatim-override path is `configOverride` (a string, since a `config:` string would
  be a map type-mismatch), which is what the e2e values use.

## ecs/

`terraform/config.example.yaml` is generated by the same `just gen` run under an ECS profile. Never
hand-edit it either; see `internal/config/AGENTS.md`.

## grafana/

Alert rules, recording rules **and** dashboards are gcx-native resource manifests
(`rules.alerting.grafana.app/v0alpha1`, `folder.grafana.app`, `dashboard.grafana.app/v2`), applied
with `gcx resources push -p deploy/grafana/<role> --context <stack>`. Manifests are stack-agnostic:
no `namespace` or stack id, gcx derives it from `--context`. They are split by **role**, not by stack
name, because the two roles live on different stacks: `self-obs/` (the integrator's own
`genai_otel_bridge_*` telemetry, deploy-by-default, push the whole directory) and `product/` (product
telemetry).

- **`noDataState` is `Ok` / `NoData`, not `OK`.** gcx returns 403 on `OK`.
- **`PollerStale` is deliberately self-relative** (twice the loop's own 6h p90 staleness baseline).
  A flat threshold false-positived roughly 100 times a day on the log-export loops. Do not "simplify"
  it back to a constant.
- **`portkey_api_*` are per-bucket gauges**, emitted only at the analytics/groups loop cadence
  (roughly 11 minutes). Aggregate them with `sum_over_time`, **never `rate()` or `increase()`**, and
  wrap an instant lookup in `last_over_time(...[20m])` - otherwise a quick query between emits reads
  as "metric absent". `genai_otel_bridge_source_graph_unavailable_total` and the
  `genai_otel_bridge_upstream_request_duration_seconds` histogram *are* counters, so `rate()` and
  `increase()` are correct there.
- **The queue metric is `genai_otel_bridge_queue_depth_ratio`, not `_depth`.** The code declares
  `queue_depth` with OTLP unit `1`, and the OTLP-to-Prometheus translation appends `_ratio`.
- `dashboard-self-obs.yaml` is generated from `gen_dashboard.py` via `just gen-dashboard`; commit the
  YAML it emits.
- The dev/test context mapping is self-obs to `self-obs-stack`, product to `product-stack`.
